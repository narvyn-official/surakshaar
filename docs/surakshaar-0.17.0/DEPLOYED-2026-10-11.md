## Delivered

- Organisation units, previewed CSV enrolment, archival and durable cohort assignment batches.
- Distinct instructor, examiner, issuer, combined assessor, author, reviewer and viewer roles, with administrator and platform operator duties separated.
- Immutable assignment policies, monitored attempt limits, practical-observation gates and independent issuance.
- Adult enrolment references, attended approval, encrypted private evidence, pinned reference versions and final-capture completion. No automated face recognition is claimed.
- Web coursework feedback/observation/cancellation; native reviewer access and records/local-procedure entry points.
- Per-institution signed learning records, public QR verification, expiry, atomic replacement, revocation and key rotation. These are formative institution records, not accredited qualifications.
- Independently reviewed local procedures, approved-only learner library, and revocable guardian/facilitator summaries.
- Platform-controlled manual allowances and restrictions. No payment is charged.
- Thirteen separate fictional demonstration accounts, one demo institute, one enrolled learner and limited demo support relationships. No passed assessment, clinical approval, identity photo or qualification was fabricated. All 13 password logins passed; nine privileged accounts require their user to enrol MFA. Existing accounts and provider settings were preserved. Passwords are in a separate local private handover, not this repository or the release.

## Deployment and recovery

Current release: `/opt/surakshaar/releases/20261011-institution-0.17.0/web`, selected by `/opt/surakshaar/current`. Web remains bound to loopback port 3197 behind the existing TLS proxy. Recovery set: `/var/backups/surakshaar/20261011-institution-0.17.0`. Previous application remains `/opt/surakshaar/releases/20261011-tinyfish-0.16.1/web`.

The private runtime now contains an AES-GCM identity/signing-storage key and an explicit demonstration platform-operator ID. Staff MFA remains enabled. TinyFish credentials, five-call daily budget, worker and disabled recurring collection are unchanged. Email recovery remains disabled. The operator can approve reviewed sources after MFA setup; sources were not auto-approved.

Retain the new encryption key and current database during recovery. Old code lacks the reference workflow required by new identity-start triggers; close monitored assessment starts if reverting. Prefer a forward repair. Do not restore a pre-release database over new users or learner activity. Local backup verification does not establish offsite disaster recovery.

## Limits

This is a controlled-evaluation release candidate. The complete proposed architecture is not finished. Cohort-restricted staff access, monitored native AR camera checkpoints and web sharing for unmonitored coursework remain software work. Google/OTP/SSO, email recovery, paid billing, managed database/object storage, offsite recovery and alerts need further integration/configuration. Qualified curricula/translations, face-liveness validation, clinical/legal review, physical-phone AR, representative load and full assistive-technology testing remain gates. Review the detailed checklist before involving real learners.
