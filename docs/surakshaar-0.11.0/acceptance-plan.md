# SurakshaAr improvement acceptance plan

4 October 2026. Baseline: local and remote `0175622`, version 0.10.0 / code 23. Remote HEAD checked directly; no later revision found. Existing hospital concept, rulebook exports and solution blueprint edits are unrelated and preserved.

Implement connected native learning, practice/replay/passport and bounded tutor slices. Keep existing assessment/certificate protocols, scenario versions 1/2, keys, installation identity and databases. New transfer practice is formative, separately stored, non-certifying and never labelled camera AR. No new external dependencies or copied assets.

Design comparison: retain Mineral Light native workspace over a dashboard-first home or immersive decoration. P005 decision-focused action panel and P024 resumable progression guide task boundaries. Home recommends one next action; Training lists courses; Progress separates knowledge, simulated procedure and practical observation. Help, language, speech and account controls stay in the profile menu. Native screen actions, explicit Back and paged overflow support large text.

Acceptance:

- Three learner destinations; one account identity; staff workspace visible after current server authorisation. Denial never grants access.
- Worked-example completion is profile/version scoped, distinct from assessment credit; fallback procedure completion never says AR evidence.
- Original procedure events can be replayed read-only; corrective retry produces separate formative evidence.
- Normal, abnormal and uncertain variations in all five domains reward appropriate refusal and escalation; critical failures cannot be averaged away.
- Every supplied question maps to context, answer/clarification/refusal, source/version, language, online/offline behavior, verification method and actual status.
- Offline question/help content remains usable without AI; draft safety material is visibly draft. No content is falsely declared competent-reviewed.
- Optional backend AI performs bounded selection of product-help references only. No generated safety instructions, assessment answers, private records, scores or permissions. Auth, tenant checks, budgets, timeouts and response validation live outside the model.
- Current builds/unit/lint/instrumentation results are recorded with build identity. Emulator results remain separate from real camera/physical/performance evidence.

External release gates: competent safety and Hindi/Santali review, approved site-specific corpus, real fire/gas device trials, representative physical performance/thermal trials, production signing arrangement, hosted-provider privacy/configuration review, production backup/restore and retention ownership. None is marked Pass without current evidence.
