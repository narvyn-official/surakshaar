# Cardboard native integration

This module vendors the Android helpers and C API from [Google Cardboard v1.35.0](https://github.com/googlevr/cardboard/releases/tag/v1.35.0), released 31 August 2026. `UPSTREAM.json` pins its archive/hash and compiler versions; `vendor/cardboard/LICENSE` retains Apache-2.0 terms. The license is also packaged in APK assets under `licenses/cardboard/`.

The app owns native SDK compilation through `app/src/main/cpp/CMakeLists.txt`. Only the GLES2 compositor and native head tracker are enabled. Unity, Vulkan, the ES3 compositor, external-storage permissions and exported NFC activity are excluded. The SDK's private QR capture Activity remains available through an explicit viewer-pairing action. Pairing can require Google Play Services' barcode assets; already paired headset rendering/lessons do not depend on a network connection. No learner identities, records or camera footage are sent by this bridge.

The unchanged Cardboard device proto is generated with `protoc 4.36.2` and linked to `protobuf-javalite 4.36.2`. This avoids adding upstream's older `3.19.4` runtime. The generated Java source is checked in so normal builds do not need a host protobuf compiler or a network generation step. Other Java dependencies follow the SDK's pinned declarations. These are implementation dependencies, not new lesson-summary or speech providers.

Two local native build adaptations preserve the upstream source: exclude the unused ES3 source from its glob and use an export map containing the enabled C API instead of missing Unity/Vulkan entrypoints. One documented source hardening patch bounds the inverse-distortion secant solver to 64 iterations, returning invalid values when it cannot converge. The bridge rejects nonfinite/invalid distortion meshes rather than guessing a viewer profile. The patch is stored in `patches/bounded-distortion-solve.patch`.

`CardboardBridge.initialise(Activity)` creates one display-scoped application context. It does not retain Activities across training sessions. `create`, `projection`, `eyeFromHead`, `headView`, `composite` and `destroy` belong to the renderer's GL owner. Pause/resume/recenter are serialized with those operations. Destroy the old handle on the owning GL thread before replacing it; do not copy or persist handles. The bridge accepts at most two concurrent handles as a defensive ownership bound.

`headView` follows the official HelloCardboard view convention: translation returned by the SDK multiplied by the SDK quaternion matrix. It is already a world-to-head view. The app supplies prediction time in Android boot-clock nanoseconds and actual display rotation. Invert the resulting view only to derive world-space gaze. Headset display is orientation tracking with the SDK's neck model; it does not provide physical room position or hand tracking.

Viewer QR parameters supply per-eye projection, eye separation and lens-correction meshes. No default is silently installed. The explicit Cardboard v1 action writes Google's original v1 profile; this does not calibrate arbitrary viewers. Fresh validated profile bytes are passed into each new renderer; changing screen dimensions or viewer parameters requires a new handle. The app supplies a single side-by-side eye texture; `composite` applies the SDK meshes to framebuffer zero.

Build with installed NDK `27.1.12297006` and CMake `3.22.1` using the project's Gradle wrapper. Native ABIs are `arm64-v8a`, `armeabi-v7a` and `x86_64`; support on an ABI is distinct from verification on a physical headset. Host math checks run with `sh scripts/test-cardboard-native.sh`. Actual lens comfort, convergence, head-motion latency and the mechanical headset button require a phone in the target viewer.
